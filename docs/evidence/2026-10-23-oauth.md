# PayPal OAuth reliability, 23 October 2026

Concurrent calls on one PayPal client now share one pending OAuth refresh. A failed refresh clears that pending request so the next call can recover. Cached tokens refresh before expiry. Empty tokens and invalid lifetimes are rejected.

The client accepts only the official Sandbox and live API origins. OAuth, order creation, capture, order lookup and webhook verification reject redirects instead of forwarding authenticated requests to another destination. This does not enable live payments or change the configured environment.

Local verification used synthetic credentials and an isolated, migrated SQLite database. All 119 tests passed, including 11 new cases for concurrent refresh, failure recovery, expiry and invalid destinations/lifetimes. TypeScript, ESLint and the Next.js production build passed.

No PayPal payment was initiated. A real Sandbox approval/capture, authenticated webhook delivery and deployed recovery-worker checks remain separate external verification tasks in `../SANDBOX_VERIFICATION.md`.
